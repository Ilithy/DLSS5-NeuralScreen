# NeuralScreen

**DLSS 5 Neural Rendering (NGX feature 18) как оверлей на весь рабочий стол Windows.**

NeuralScreen захватывает весь экран, прогоняет каждый кадр через нейронный
рендеринг NVIDIA (тот же feature 18, что используют игры с DLSS 5) и рисует
результат поверх рабочего стола в окне, прозрачном для кликов.

```
захват экрана -> motion guides -> NGX-воркер (D3D12) -> оверлей на весь экран
  в воркере        cv2 DIS 320x180     native/nvngx.dll      окно воркера + HUD
```

> **Альфа (v0.1.0+).** Весь конвейер живёт на GPU: захват (Desktop
> Duplication), нейронный проход и вывод — внутри воркера; Python считает
> только guides оптического потока (0.1–0.2 мс/кадр). Замерено на RTX 5070 Ti,
> рабочий стол 4K, work 1920×1080: **32 FPS с NR, 64 FPS в режиме NR off
> (bypass)**. Подробности — в «Производительность».

## Требования

- **Windows 11** (нужен Desktop Duplication API и `WDA_EXCLUDEFROMCAPTURE`)
- **NVIDIA RTX** с поддержкой DLSS 5 Neural Rendering. Разрабатывалось и
  проверялось на RTX 5070 Ti, драйвер 616.56, 4K (3840×2160)
- **Python 3.13** с пакетами из `requirements.txt`
- **`native/nvngx_dlssnr.dll`** — рантайм NVIDIA (165 МБ). В репозитории его
  нет (лимит GitHub 100 МБ) — взять из ассетов релиза и положить в `native/`
- Для пересборки воркера — **MSVC 2022 Build Tools** (см. «Сборка»)

## Запуск

1. Скачать архив релиза (или клонировать репозиторий и добавить
   `native/nvngx_dlssnr.dll` из ассетов релиза).
2. Двойной клик по `NeuralScreen.bat`. Лаунчер ищет Python в таком порядке:
   переменная `NEURALSCREEN_PYTHON` → `runtime\python.exe` рядом с программой →
   путь разработки → `python` из `PATH`. Если воркер `native/nvngx.dll` не
   собран, лаунчер соберёт его сам.
3. Консоль не закрывается специально: в неё пишутся FPS и тайминги конвейера.

> Внимание, анти-чит: процесс с именем `nvngx.dll` плюс полноэкранный оверлей
> могут не понравиться EAC/BattlEye/Vanguard. Не запускайте NeuralScreen в
> соревновательных онлайн-играх.

## Управление

| Клавиша | Действие |
|---|---|
| `F9` | NR вкл/выкл. **Выкл — это bypass**: оверлей остаётся на экране (сырой захват + HUD, без эффекта), а рабочий стол работает вдвое быстрее. Всё прячется только при настоящем выходе. |
| `F8` | окно настроек |
| `Ctrl+Alt+↑` / `Ctrl+Alt+↓` | масштаб обработки ±0.05 |
| `Ctrl+Alt+Q` | выход |

Хоткеи регистрируются через `RegisterHotKey`, а не опрашиваются: система
доставляет нажатие **только нам и не передаёт активному приложению** — F9
в игре переключает NR, и сама игра этой клавиши не видит. Обратная сторона:
пока NeuralScreen запущен, F8 и F9 принадлежат ему.

Стрелки и выход сделаны на `Ctrl+Alt` намеренно: голые стрелки регистрировать
нельзя (перестали бы работать во всей системе), а выход по одиночной клавише
слишком легко нажать случайно.

Иконка в трее: левый клик — настройки, правый — меню (NR вкл/выкл, масштаб,
выход). В окне настроек — профиль, слайдеры параметров NR, масштаб, язык
(ru/en), кнопка скриншота и **Выход**.

Три способа закрыть программу делают разное, поэтому названы по-разному:

| | Что делает |
|---|---|
| `Ctrl+Alt+Q`, «Выход» в настройках, «Выход» в трее | завершают программу: воркер погашен, окна закрыты, процессов не остаётся |
| «Закрыть» в окне настроек и крестик | только прячут окно настроек, программа продолжает работать |

Оверлей click-through (`WS_EX_TRANSPARENT | WS_EX_LAYERED | WS_EX_NOACTIVATE`
плюс `HTTRANSPARENT`) — клики и фокус уходят приложениям под ним. Окна
исключены из захвата (`WDA_EXCLUDEFROMCAPTURE`), иначе Desktop Duplication
снимала бы наш же вывод и получилась бы обратная связь. Следствие: **заснять
оверлей внешним скриншотером/записью невозможно** (OBS, Lightshot увидят
рабочий стол без него) — для этого есть кнопка Screenshot в настройках, она
берёт кадр у воркера, а не с экрана.

## config.json

| Поле | Смысл |
|---|---|
| `monitor` | индекс монитора для захвата |
| `width`, `height` | разрешение вывода |
| `fullscreen` | безрамочное окно на весь монитор |
| `warmup` | прогревочные кадры NGX при старте |
| `work_scale` | 0.25–1.0, разрешение обработки NGX относительно вывода |
| `profile` | `Faithful`, `Natural`, `Strong / Cinematic`, `Extreme / Overdrive` |
| `intensity`, `local_tone`, `local_structure`, `skin_structure` | `null` = взять из профиля |
| `lang` | `ru` / `en` |
| `worker_present` | воркер показывает кадр в своём окне (`false` — вывод через pygame) |
| `motion_on_gpu` | поле движения растягивает воркер (`false` — считать на CPU) |
| `capture_in_worker` | воркер захватывает экран сам (DDA; `false` — dxcam в Python) |

Три булевых флага — аварийные выключатели: если что-то пойдёт не так на
другой машине, `false` возвращает старый путь, который никуда не удалён.

## Архитектура

Два процесса. Python ведёт настройки, guides оптического потока и HUD;
C++-воркер владеет D3D12-устройством, захватом, NGX и окном оверлея.
Общаются через stdin/stdout бинарным протоколом:

| Сообщение | Назначение |
|---|---|
| `D5V3` | заголовок потока: размеры, профиль, параметры NR |
| `SHMI` / `SACK` | имя общей памяти под входной кадр |
| `WNDO` / `WACK` | поднять/закрыть окно вывода воркера |
| `MOTS` / `MACK` | поле движения приходит уменьшенным, растягивает воркер на GPU |
| `DDA1` / `DACK` | воркер забирает захват (Desktop Duplication), цвет не касается CPU |
| `GRAY` / `GAK` | воркер пишет AREA-luminance (320×180) в обратный маппинг для guides |
| `FRM1` | кадр: заголовок, дальше либо тело (RGBA8 + motion), либо флаг «в общей памяти» |
| `OUT1` | результат: RGBA8 full-res, либо `bytes=0` — кадр уже показал воркер |
| `RNSZ` / `RACK` | смена work-разрешения на лету, без рестарта процесса |

**Захват.** По команде `DDA1` воркер открывает Desktop Duplication на GPU:
кадр копируется в кросс-устройственную shared-текстуру и своппится в RGBA.
Python вообще перестаёт захватывать — `grab` и `guides` в логе падают до
0.1 мс. Фолбэк (dxcam + передача кадра целиком) остался нетронутым.

**Guides.** Оптическому потоку нужен маленький серый кадр. По команде
`GRAY` воркер считает его честным блочным усреднением (блок 12×12 при 4K →
320×180, как `cv2.INTER_AREA`; билинейная выборка дала бы алиасинг на тексте
и сломала поток) и пишет в именованный маппинг. Python читает вход потока
оттуда — полный 4K-кадр больше не пересекает CPU.

**Вывод.** По команде `WNDO` воркер поднимает своё безрамочное окно на весь
экран с D3D12-swapchain и показывает результат NGX сам: `OUT1` приходит
пустым, пиксели в Python не возвращаются вовсе. Окно pygame остаётся слоем
HUD — фон заливается цветом-ключом и делается прозрачным (`LWA_COLORKEY`),
перерисовка идёт ~10 раз в секунду вместо каждого кадра. Окно воркера
исключено из захвата — без этого DDA снимала бы наш же вывод.

**NR off (bypass).** `F9` больше не останавливает конвейер. Кадры уходят с
флагом `FRAME_FLAG_BYPASS`: воркер пропускает NGX evaluate и показывает сырой
захват. Оверлей (картинка + HUD) остаётся живым и предсказуемым; всё прячется
только при настоящем выходе. Следующий кадр без флага возобновляет нейронный
проход.

**Скриншот** в режиме окна воркера делается флагом `FRAME_FLAG_WANT_PIXELS`:
для одного кадра воркер и покажет его, и вернёт пиксели.

**Поле движения.** По команде `MOTS` клиент шлёт его в разрешении
оптического потока (320×180, 0.23 МБ) вместо work-разрешения (12 МБ), а
растягивает воркер вычислительным шейдером. Билинейная интерполяция считается
вручную во float32, а не аппаратным сэмплером (у того веса квантуются до
1/256 текселя). Формула повторяет `cv2.resize(INTER_LINEAR)`. Расхождение с
CPU-путем на финальном кадре NGX — сотая доля пикселя.

**Общая память.** Входной кадр идёт через именованную секцию: воркер грузит
пиксели в текстуру прямо из маппинга, в пайп уходит только 24-байтовый
заголовок. Раскладка фиксирована и не зависит от `work_scale` (RGBA8
full-res, motion со смещения `full_w*full_h*4`), поэтому смена разрешения не
требует перевыговаривания. Слот один: следующий кадр можно класть только
после ответа воркера на предыдущий.

Два ограничения, которые выглядят как странности, но обязательны:

- **Имя воркера обязано быть `nvngx.dll`.** NGX Core возвращает
  `FAIL_PlatformError` на `Init_Ext` для любого другого имени процесса.
  Проверено экспериментально.
- **work-разрешение ограничено 2560×1440.** На 4K feature 18 молчит: воркер
  зависает на нулевом кадре и в legacy-, и в upscale-режиме.

Смена масштаба идёт через `RNSZ` (~60 мс, воркер пересоздаёт NGX feature у
себя, окно и захват не трогаются). Если `RNSZ` не прошёл — фолбэк на полный
рестарт процесса воркера.

## Производительность

Замерено на RTX 5070 Ti, рабочий стол 4K, `work_scale` 0.5 (1920×1080),
статичный экран, конвейер полностью на GPU (DDA + GRAY + WNDO + MOTS):

```
NR ON :  guides 0.1ms | send 0.0ms | recv 30.3ms | show 0.7ms  -> 32.0 FPS
NR OFF (bypass):       recv 15.0ms | show 0.4ms              -> 64.0 FPS
```

Путь оптимизации (тот же стенд, тот же режим):

| Состояние | Кадр | FPS |
|---|---|---|
| кадр и результат через stdio-пайпы | ~50 мс | 19.5 |
| входной кадр через общую память | ~46 мс | 21.9 |
| вывод в окне воркера | ~26 мс | 36–39 |
| поле движения растягивает GPU | ~24 мс | 38–41 |
| захват в воркере (DDA) + guides из gray | ~31 мс | 32.0 |
| **NR off через bypass** | **~16 мс** | **64.0** |

Собственно **NGX — около 1 мс**. Остальное — конвейер: `recv` не зависит от
work-разрешения (31 мс и на 384×216, и на 2560×1440). Кадры с NR идут в
ритме 2 vblank при 60 Гц (30 мс), bypass — 1 vblank (15 мс); выравнивание
фазы захвата/Present — следующая цель оптимизации (план — в заметках
проекта).

На реальном движении растёт стоимость guides (DISOpticalFlow на 320×180 ≈
1.4 мс + растяжение), но остаётся пренебрежимо малой на фоне `recv`.

## Сборка воркера

```
native\build-host.bat
```

Нужны MSVC 2022 Build Tools по пути
`C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools`. Скрипт
собирает `dlss5-feed-host64.cpp` в `native/nvngx.dll`, линкуясь с
`native/lib/Windows_x86_64/x64/nvsdk_ngx_d.lib`. Заголовки NGX — в
`native/include/`.

Артефакт `native/nvngx.dll` в репозиторий не кладётся.

## Известные ограничения

- Только Windows, только NVIDIA RTX с DLSS 5 NR.
- work-разрешение упирается в 2560×1440 (ограничение NGX, см. выше).
- Полноэкранные эксклюзивные игры: оверлей рассчитан на рабочий стол и
  оконные приложения без рамки; при смене режима дисплея конвейер сбрасывается.
- Сквозная задержка 40–60 мс — свойство цепочки захват → NGX → показ;
  заметна при перетаскивании окон.
- Анти-чит: `nvngx.dll` + оверлей — красный флаг для EAC/BattlEye/Vanguard.
- На статичном рабочем столе оптический поток отключается по порогу
  `scene_score` — motion не считается, кадры идут дешевле.
